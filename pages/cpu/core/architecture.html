CPU Architecture Deep Dive

How processors are designed internally — from Von Neumann's 1945 model to today's out-of-order superscalar chips with billions of transistors.

“– What is CPU Architecture?

CPU architecture (also called microarchitecture or ISA design) refers to the internal design and organization of a processor. It determines how the CPU fetches, decodes, executes, and stores data. Two CPUs can share the same instruction set (like x86-64) but have completely different internal architectures — for example, Intel's Raptor Lake vs AMD's Zen 4.

Architecture decisions affect everything: speed, power consumption, heat output, die size, and cost. Understanding CPU architecture is the key to understanding why one processor outperforms another.

Every modern desktop CPU uses Modified Harvard Architecture — they have separate L1 instruction and L1 data caches (Harvard-style), but share a unified L2/L3 cache and main RAM (Von Neumann-style).

The two dominant philosophies for instruction set design:

FeatureCISC (Complex Instruction Set)RISC (Reduced Instruction Set)
PhilosophyMany complex instructions, each does a lot of workFew simple instructions, each completes in one clock cycle
Examplesx86 (Intel, AMD)ARM (Apple, Qualcomm), RISC-V, MIPS, PowerPC
Instruction lengthVariable (1-15 bytes for x86)Fixed (4 bytes for ARM)
RegistersFewer general-purpose (16 in x86-64)More general-purpose (31 in AArch64)
Memory accessInstructions can directly operate on memoryLoad/Store — only specific instructions access memory
DecodingComplex — variable-length instructions are hard to decodeSimple — fixed-length instructions decode fast
Power efficiencyHigher power consumptionLower power — dominates mobile
Modern realityx86 CPUs internally convert CISC to RISC-like micro-opsARM CPUs have grown more complex over time

Key insight: The CISC/RISC distinction has blurred significantly. Modern x86 CPUs (Intel/AMD) decode their complex instructions into simple micro-operations (µops) internally — essentially running a RISC engine under a CISC instruction set.

”§ Pipelining & Superscalar Design

Pipelining is the technique of overlapping instruction stages (fetch, decode, execute, write-back) so multiple instructions are in-flight simultaneously, like an assembly line:

Clock CycleStage 1Stage 2Stage 3Stage 4
Cycle 1Fetch I1———
Cycle 2Fetch I2Decode I1——
Cycle 3Fetch I3Decode I2Execute I1—
Cycle 4Fetch I4Decode I3Execute I2Write I1

Superscalar design takes this further — the CPU has multiple execution units and can process 4-8+ instructions simultaneously in the same clock cycle. Modern CPUs like Zen 4 and Golden Cove can dispatch 6+ µops per cycle.

””Out-of-Order Execution (OoOE)

Most modern CPUs execute instructions out of program order to maximize throughput. If Instruction #3 is waiting for data from memory, the CPU can skip ahead and execute Instructions #4, #5, #6 if they don't depend on #3's result.

Key components enabling OoOE:

ComponentFunctionSize (Modern CPU)
Reorder Buffer (ROB)Tracks all in-flight instructions to ensure results are committed in correct order512 entries (Zen 4), 512 (Golden Cove)
Reservation StationsHold instructions waiting for their operands to become available~200 entries
Register RenameEliminates false dependencies by mapping logical registers to a larger physical register file192+ physical registers
Branch PredictorGuesses the outcome of branch instructions to keep pipeline full97%+ accuracy (TAGE predictor)
